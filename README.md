# RippleTrack — Web Application

**Team: Tifosi CodeWorks | IBM Bob 2.0 Hackathon**

RippleTrack is an interactive web app that lets you pick a PRD from a curated library,
watch three AI subagents analyze it live, and explore the full Ripple Map + Risk Score on an interactive dashboard.

---

## Two-command startup

Open **two terminals** in the project root:

### Terminal 1 — Backend API (port 3001)
```bash
node server/index.js
```

### Terminal 2 — Frontend (port 5173)
```bash
cd frontend && npm run dev
```

Then open **http://localhost:5173** in your browser.

---

## What's in the app

### New Analysis page (default)
- **PRD Library** — 7 pre-validated PRD cards, each with a risk band badge and a "Run RippleTrack" button.
- **Live progress** — three parallel agent status cards (Contract Detective / Code Archaeologist / Test Archaeologist)
  that update via polling as the analysis runs.
- **Advanced Mode** (collapsed section) — drag-and-drop upload of a custom PRD, with an explicit experimental warning badge.

### Dashboard page (per run)
- **Ripple Map** — interactive node graph (React Flow) colored by node type (model / consumer / fixture / test),
  with risk flag counts on each node and hover detail.
- **Risk Score gauge** — 0–100 SVG arc gauge, Low / Medium / High bands, expandable factor breakdown table.
- **Signal Registry** — sortable table of all `ripple_signals` rows generated by this run.
- **CI Verification** — "Run CI Simulation" button with before/after test results.

### Run History page
- Table of all past runs, flagged Library vs Advanced Mode, linking into each dashboard.

## API endpoints (Part A)

| Method | Path | Description |
|--------|------|-------------|
| GET | `/health` | Liveness check |
| GET | `/api/prd-library` | List of pre-loaded PRDs |
| POST | `/api/analyze` | Start a new analysis (library or advanced upload) |
| GET | `/api/runs` | List of past runs |
| GET | `/api/runs/:id` | Full run detail (Ripple Map, Risk Score, signals) |
| GET | `/api/runs/:id/status` | Live agent progress (poll during analysis) |
| POST | `/api/runs/:id/ci-simulate` | Trigger CI simulation for a run |
| GET | `/api/signals` | Full Signal Registry across all runs |
| GET | `/api/repos` | List valid target repos |

### POST /api/analyze — library path
```json
{ "prd_id": "prd-rt-8821", "target_repo_id": "rippletrack-demo" }
```

### POST /api/analyze — advanced upload
```
multipart/form-data
  prd_file: <file>
  mode: "advanced"
  target_repo_id: "rippletrack-demo"
```

Returns `{ run_id, status: "queued", mode }` immediately. Poll `/api/runs/:id/status` for progress.

## Demo script (3-minute recording path)

1. Start backend: `node server/index.js`
2. Start frontend: `cd frontend && npm run dev`
3. Open http://localhost:5173
4. Click **"▶ Run RippleTrack"** on `requirements_v3.docx` (High risk, primary demo)
5. Watch three agent cards animate through `pending → running → done`
6. Dashboard loads automatically → show Ripple Map, Risk Gauge (100 / High)
7. Expand Risk Factor Breakdown → all 6 factors triggered
8. Click Signal Registry tab → show RT-8821 row
9. Click CI Verification tab → Run CI Simulation → before/after test results
10. Navigate to Run History → show all past runs
