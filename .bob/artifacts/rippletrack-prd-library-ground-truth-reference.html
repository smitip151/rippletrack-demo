Files the Change Touches
FileWhy
src/models/UserProfile.tsType of preferredLanguage changes from string to the new LanguageCode enum. Schema drift against current type.
src/api/userRouter.tsRoutes that write preferredLanguage accept any string today — must now validate against the enum.
tests/mocks/userFixture.jsonValue "en-US" is a valid enum member, but the fixture type annotation (if any) must be updated.

Expected Risk Band & Factors

High / Schema Drift

  • Schema drift — an existing field's type narrows from string to enum; any callsite supplying an arbitrary string now violates the contract.
  • Existing consumer impact — router writes, analytics reads, and the fixture are all coupled to the old type.
  • PRD contract is otherwise well-specified (default stated, optionality stated), so Contract Detective should flag type change on live field as the primary risk factor.

Intentional Ambiguities in the PRD Text
ClauseWhat's Missing / Vague

Expected Contract Detective Flags
  • Missing optionality declaration — Contract Detective should raise "cannot determine required vs optional" and refuse to infer.
  • Missing default — "not specified" should be an explicit Contract Detective output, not a silent assumption of undefined.
  • Open enum — type is described as a soft set with possible future values; parser should flag "type constraint underspecified".
  • Unnamed consumers — "downstream services" without names should trigger "consumer tracing not possible — dependency unknown".

Risk band is intentionally indeterminate — the point of this PRD is to show the system asking a clarifying question rather than making a guess.
